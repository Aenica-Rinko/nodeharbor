# 代码与桌面布局审查 · 2026-10-27

## 范围与方法

审查面向可分发源码、测试、脚本、示例配置、文档和许可证，不把私人运行配置、节点缓存、导出、日志或备份混入交付。原始公开清单为 100 个文件：44 个应用模块、21 个测试文件、8 个脚本、10 个文档/图片/第三方许可文件，以及入口、元数据、示例和仓库配置。新增本报告后共 101 个文件。

对公开清单执行文件与隐私规则检查、Python 语法解析及完整回归测试；重点人工追踪搜索/下载、解析/检测、节点库、导出事务、任务取消、设置保存与桌面呈现。并非对所有文件的每一行都做了人工形式化验证，也不是第三方安全认证。

## 已修复

- 设置写入没有与后台任务共享锁，可能覆盖并发修改。现在保存持有应用锁，比较页面打开时与提交前的配置快照；导出目录迁移也在复制前检查快照。
- 节点表刷新或排序会丢失选中对象。现在按节点身份恢复选择；损坏的历史 `recent` 字段不再导致页面异常，读取失败时清除旧缓存。
- 导出页把“最近检测失败”与“超过 60 分钟”混为一谈。现在分别提示，保留重新检测入口。
- 尚未生成 Mihomo 文件时不再拼接无效的代理地址，端口有有效整数值时才显示地址。
- 日志页曾完整读取日志文件再截取。现在只读取末尾最多 60 KB，并为日志提供独立滚动条。
- 搜索窗口在高 DPI 下，长描述与换行操作挤压结果。说明改为固定高度可滚动区域，高缩放且屏幕高度不足时采用紧凑布局；取消与添加入口保留。
- 对话框鼠标滚轮不再带动主窗口；底部取消状态在其他页面同样可见。

## 视觉方向与落地

参考 Fluent 2 的信息层级与间距、Carbon 的数据表布局、VS Code 的导航与状态区域分工，形成“导航—主操作—筛选—数据—选中详情—任务状态”的稳定结构。具体依据见 [桌面布局说明](ui-layout.md)。

来源与节点默认显示五列，低频信息移到下方详情；高级设置默认收起。主操作集中到页头，任务完整统计集中到“任务与诊断”，底部始终保留阶段进度和取消入口。导出页一次生成三个客户端文件，各卡片仅保留状态、文件入口和按需展开的导入帮助。统一输入框、表头、边框与主次按钮颜色，缩窄侧栏。

布局检查使用临时配置和虚构节点，未使用个人节点截图。主页面覆盖 100%、125%、150%、200% 字体缩放；搜索窗口覆盖 100%、150%、200%，检查按钮边界和列表最低可用高度。真实窗口目视检查覆盖来源、节点库和导出页；其余页面通过布局与交互测试检查。

## 验证边界

最终全量回归为 311 项通过、1 项旧按钮文案断言失败；同步断言后该项单独复测通过，312 项均已有通过记录。公开清单 101 个文件通过隐私规则检查，所有公开 Python 文件通过语法解析。

冻结 EXE 的独立安装检查通过：移除子进程 Python 路径后，初始化、全部页面、来源维护、三客户端文件、诊断报告、核心选择与任务进度、后台管道、工作进程复用与取消均完成。最后的空状态文案修正另通过 17 项客户端导出测试。

本机 Python 的 Tcl/Tk 在多实例测试中偶发初始化错误，相关跳过项需单独复测。发布包另用不依赖系统 Python 的冻结程序检查初始化、所有页面、来源维护、客户端导出、诊断、进程管道与取消。

测试使用临时数据和回环服务；现有 Mihomo 隔离启动检查不等于每个公共节点均可用。GitHub 搜索限流、第三方来源失效、Cloudflare 候选搜索范围有限，仍然是外部约束。未进行全网节点数量统计或所有客户端版本的真实流量验收。

本轮只更新本地源码和构建，没有发布或修改 GitHub 仓库。没有删除用户配置、历史节点、导出或备份，也没有为了外观更换 GUI 框架。

## 后续优先级

1. 用首次使用者完成“配置核心—选择来源—获取节点—导入客户端”的任务测试，记录卡点、耗时及失败后的恢复路径。
2. 固定可复现的 Windows GUI 测试环境，建立空状态、运行中、失败和完成状态的截图回归；进一步检查键盘焦点、屏幕阅读器和对比度。
3. 在应用层增加视图模型接口，逐步减少页面对 Desktop 混入类和共享字段的依赖；保持现有任务、存储和导出事务边界。
4. 按真实诊断统计改进来源维护和失败重试，不以持续增加来源数量代替成功率与结果可信度。

当前项目已经具有完整的获取、检测、维护与三客户端导出流程，适合作为持续打磨的 Beta 工具。下一阶段最有价值的是可复现验证和实际使用反馈，不能仅凭测试数量宣称已经毫无缺陷。
