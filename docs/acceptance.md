# 桌面流程与客户端验收

本记录包括 2026-10-27 的本地改进和 2026-10-28 的客户端补充验收，尚未发布到 GitHub。自动化场景使用临时配置和虚构节点；代理流量仅在专用回环测试中产生。图形客户端导入的测试数据与清理情况见后文。

## 首次使用流程

`tests/test_desktop_workflow.py` 的首次使用用例覆盖：空配置 → 配置检测核心 → 添加默认停用的来源 → 手动启用 → 获取节点 → 确认尚未导出 → 显式生成三个客户端的文件 → 复制 v2rayN 链接。

该用例使用真实页面、任务调度、节点库和导出逻辑，网络和核心检查使用测试替身。它验证流程衔接，不等于邀请真实新用户完成任务。人工体验测试仍应记录：首次完成耗时、无法理解的词语、失败时能否找到原因、取消后能否继续操作。

本轮修正：导出完成后的下一步指向导入客户端；v2rayN 直接复制节点链接；没有可转换节点时不显示成功；复制使用最近完整生成的版本；导入帮助说明本地文件副本的更新方式。按钮支持 Enter 触发。

## 独立进程 GUI 检查

```text
python -B scripts/windows/check_ui.py
```

覆盖空配置、来源列表、已获取节点、已导出、运行中、失败、取消和 Cloudflare 搜索结果，共 8 个场景；分别以 100%、125%、150%、200% 的 Tk 缩放执行，共 32 个独立进程。Tcl/Tk 初始化失败或布局断言失败均会返回错误，不按跳过处理。运行中等任务状态使用演示数据，真实后台取消另外由工作流测试和冻结程序安装检查覆盖。

自动检查主要按钮宽度与横向边界、底部操作区、搜索列表最低高度、搜索按钮是否被父容器裁切、失败或取消时既有导出的保留，以及导出后工作台引导。Tk 缩放模拟不能替代跨显示器切换和真实 Windows DPI 设置检查；该脚本也不是自动截图像素比较工具。

可打开相同场景人工检查：

```text
python -B scripts/windows/check_ui.py --case exported --scale 1 --preview
python -B scripts/windows/check_ui.py --case cloudflare --scale 1.5 --preview
```

演示窗口三分钟后自动关闭。截图基线应使用上述临时场景，记录系统缩放、窗口尺寸与 Tk 版本，检查主次操作层级、留白、文字截断、滚动后的操作可达性，以及 Tab / Enter 键盘操作。截图仅保存在本机验收目录，不含真实订阅、日志或私人路径。本轮已目视核对导出页和完成后的工作台，其他状态采用布局与交互断言；尚未完成屏幕阅读器验收和自动像素差分。

## 客户端检查

只做格式检查：

```text
python -B scripts/windows/check_clients.py --format-only
```

使用自行安装的核心执行真实配置检查：

```text
python -B scripts/windows/check_clients.py --mihomo "<mihomo.exe 路径>" --verge-core "<verge-mihomo.exe 路径>"
```

脚本通过实际导出器生成 SS、VMess、VLESS、Trojan、Hysteria2、TUIC、AnyTLS 七种虚构节点，检查认证字符与传输字段往返、Base64 内容一致性、YAML 运行设置边界，再调用指定核心的配置校验。测试配置不连接外网，不启动代理服务。本轮由此发现并修复了 VMess 缺省 `alterId` 导致核心拒绝配置的问题，现在规范化为 0，并保留显式值。

| 验证对象 | 本机结果 | 边界 |
| --- | --- | --- |
| Mihomo v1.19.24 | 七种协议配置通过真实核心检查；SS 本地代理流量通过 | 未测公网节点流量 |
| Clash-Verge-Rev v2.5.8 / 内置 Mihomo v1.19.32 | 实际导入七种协议 YAML；导入副本字段与导出一致 | 未测 GUI 更新订阅 URL、所有协议真实流量 |
| v2rayN v7.25.6 x86 | 实际粘贴导入七种协议；认证及 WS / gRPC 字段一致 | 未测所有协议真实流量及其他版本 |

图形客户端实际验收应在独立测试配置中进行：Clash-Verge-Rev 新建本地订阅或拖入 `free.yaml`，检查协议、名称、数量和配置加载错误；v2rayN 在节点列表粘贴“复制节点链接”的内容，逐项核对认证字段及 WS / gRPC 参数。不启用系统代理或用虚构节点尝试访问网络。更新导出后重复导入，核对新增/移除行为。真实流量验收则需要另行准备可控的有效测试服务，不能据本记录宣称公共节点持续可用。

导入行为依据：[Clash-Verge-Rev 配置指南](https://www.clashverge.dev/guide/profile.html)、[v2rayN 界面操作说明](https://github.com/2dust/v2rayN/wiki/Description-of-some-ui)、[v2rayN 订阅说明](https://github.com/2dust/v2rayn/wiki/Description-of-subscription)。

## 2026-10-28 实际导入与流量补充验收

Clash-Verge-Rev 使用单独命名的虚构订阅，通过“新建 → 本地 → 选择文件”导入；核对客户端写入的七个节点与 NodeHarbor 输出完全一致。将 NodeHarbor 测试导出改为六个节点后，客户端的原本地副本仍为七个，确认不会自动同步。测试订阅条目与文件已移除，其他订阅条目保留，系统代理和 TUN 仍关闭。

v2rayN 使用本地程序的独立副本，不复制原来的配置、数据库或日志。从 NodeHarbor 的“复制节点链接”按钮复制，实际按 Ctrl+V 导入七个节点。只读核对测试副本数据库，名称、服务器、端口、密码特殊字符、UUID、WS Host/路径和 gRPC 服务名均保持一致。第二次导入六个改名改端口节点后，数量成为十三个，原七个仍在。已在产品导入帮助中说明“粘贴会追加，不会移除旧节点”；测试副本已关闭。

新增可复现的本地流量检查：

```text
python -B scripts/windows/check_traffic.py --mihomo "<客户端 mihomo.exe>" --upstream-mihomo "<服务端 mihomo.exe>"
```

脚本运行实际导出器，使用 SS / aes-256-gcm 虚构凭据，建立“HTTP 请求 → Mihomo 客户端 → Mihomo SS 服务端 → 本地 HTTP 服务”的真实数据通路。测试专用配置将虚构域名映射至回环地址，并将健康检查 URL 改成本地服务；保留导出的凭据、策略组、规则及监听选项。服务端只允许访问该测试端口，所有监听均为回环地址，进程在结束时回收，不改系统代理。

Mihomo v1.19.24 客户端与 v1.19.32 服务端组合成功返回预期内容；停止 SS 服务端后再次请求失败，排除了直连回退造成的假阳性。早期使用 Xray v26.10.10 作为测试服务端时，其日志明确拒绝回环目标，因此未将该组合记为通过；最终测试改用上述独立 Mihomo 服务端。SS 服务端配置参考 [Mihomo listeners 文档](https://wiki.metacubex.one/config/inbound/listeners/ss/)。

本轮没有验证公网节点长期可用性、UDP/QUIC 流量或七种协议的完整握手矩阵。图形导入和单协议本地传输通过，足以支持 Beta 发布准备，不能据此承诺所有公共来源与客户端版本均可用。导入引导修改后，17 项客户端导出回归测试通过。

## 持续集成

CI 在全部测试平台运行客户端格式检查，在 Windows / Python 3.13 运行 32 个 GUI 场景；真实核心检查使用本机明确提供的可执行文件。发布前还应执行公开文件隐私检查和冻结 EXE 安装检查，不能只依据单元测试数量判定可以发布。

本轮本机全量 pytest：315 项通过，1 项因重复初始化 Tcl/Tk 跳过；该项单独运行通过。桌面模块复测中另一次出现的设置测试初始化跳过也已单独通过。这仍是本机同进程多 Tk 实例的测试环境限制，不能说全量运行零跳过。新增的 32 个独立进程场景全部通过（Tk 8.6.15），公开清单 104 个文件通过隐私规则检查。规则扫描只能证明未命中检查规则，不能替代人工对敏感信息的判断。

## 2026-10-29 本地体验改进

本地开发版本为 `1.3.0b2.dev0`，没有发布或替换 GitHub Beta 1。新增可换行输入操作组件、节点检测证据和来源贡献说明，核心设置及复制导入帮助更明确。首页与完整指南分离，三张截图由隔离演示窗口生成，不含私人配置。

全量回归 318 项通过，2 项因同进程 Tk 初始化跳过；这两个用例随后分别在独立进程通过。32 个独立界面场景通过；新增输入布局回归覆盖宽、窄、恢复宽窗口，以及未知检测结果、历史复用和重复来源说明。

新用户试用方案见 [试用记录](usability-check.md)。尚未开展真人试用，也未扩大公网、UDP/QUIC 和客户端版本的实际流量验收范围。
