# 桌面布局改进依据

## 参考与取舍

- [Fluent 2 Layout](https://fluent2.microsoft.design/layout)：用统一间距和接近程度表达信息层级，避免依赖大量卡片标题。
- [Fluent 2 Navigation](https://fluent2.microsoft.design/components/web/react/core/nav/usage)：导航围绕用户任务命名，减少次要操作。
- [Carbon Data Table](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)：列表为主体，搜索筛选放工具栏，详细信息按选择展开。
- [VS Code UX](https://code.visualstudio.com/api/ux-guidelines/overview)：区分导航、工作内容、辅助面板和状态栏。

这些原则用于现有 Tk 桌面应用，不需要为了外观更换技术框架。

## 本次落地：搜索节点池

顶部依次为标题、搜索类型、范围提示和搜索框；中部左右分栏显示公开出处与候选订阅；底部保留操作说明和关闭入口。长地址支持横向滚动，操作在较窄面板内换行。搜索状态直接显示在对话框内，不要求用户观察被遮挡的主窗口。

GitHub 与 Cloudflare 模式共用搜索、取消、预览和添加流程。Cloudflare 标签描述的是订阅文件的托管位置，公开出处仍显示 GitHub 仓库。候选订阅、节点可用性和已导出文件是三个不同状态，不使用同一“成功”提示代替。

## 整页重排已实施

1. 主窗口集中显示一个紧凑任务栏；完整统计放“任务与诊断”，避免每页顶部重复的大进度卡片挤压列表。进度仅表示当前阶段，不拼成虚假的全程百分比。
2. 公开源采用页头主操作、搜索筛选、列表和下方选择详情。高级参数、预设和手动添加默认收起；托管类型作为稳定筛选项。列表默认保留五列，解析和送检数量在详情查看。
3. 免费节点默认显示名称、协议、检测结果、延迟和来源类型；跨轮历史、失败次数和完整服务器信息放详情，减少十列同时出现。
4. 导出页保留一个“生成 / 更新导出文件”主操作，三个客户端使用一致的文件状态、打开目录和导入说明。
5. 设置保存和诊断报告入口位于各自页头；日志有独立滚动条，只读取文件末尾有限内容。对话框滚轮不再同时驱动主窗口。
6. 搜索窗口的远端描述和状态提示使用有滚动条的固定高度区域，防止长文字挤掉结果。高 DPI 且屏幕高度不足时减少重复标题并采用紧凑说明区。

统一使用浅灰背景、白色工作区、深蓝正文、蓝色主操作；边框、表头、输入框和禁用状态共用一组颜色。侧栏按“工作台 → 公开源 → 免费节点 → 订阅导出”排列。

## 验证与限制

使用临时配置和虚构节点检查真实 Tk 窗口；布局回归覆盖 100%、125%、150%、200% 字体缩放，搜索对话框覆盖 100%、150%、200%。测试检查按钮边界与列表最低可用高度。

仍保留整页滚动作为小屏兜底，设置页和高 DPI 下的长内容需要滚动。Tk 控件与概念图不会逐像素一致。下一步应优先进行真实用户任务测试和键盘可达性检查，而不是继续增加卡片、按钮或装饰。

## 2026-10-29 输入与操作布局

设置中的核心路径、导出路径与来源搜索共用 `input_actions` 组件。宽窗口保持输入与操作同行，空间不足时把操作移到下一行，避免输入框抢占按钮空间。组件覆盖从宽到窄再恢复的回归检查。节点详情展示实际检测时间、复用标记、单次轮数和跨次记录；来源详情展示候选、保留、复用与重复比例，不把独有数量当作可用数量。
