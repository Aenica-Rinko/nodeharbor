# 架构与数据约定

## 入口与模块

`desktop.py` 与 `cli.py` 调用同一个 `pipeline.execute()`，桌面线程通过队列向 Tk 主线程传递进度。运行时只读取 `settings.yaml`；旧的私人配置和秘密文件不读取、不重写。

| 模块 | 职责 |
| --- | --- |
| storage / config / initialize | 目录、原子写入、锁、配置校验与核心发现、空白初始化 |
| public_sources / fetcher / download_network / source_plan | 公开 GitHub 来源、TLS 下载、代理回退、缓存、条件请求、限流、来源健康排序与公平分配候选 |
| source_catalog / github_search / source_search_dialog | 仓库搜索、候选文件选择、默认停用的自选节点池与启停持久化 |
| node_library | 内部节点库原子更新、兼容旧导出读取、待导出标识 |
| nodes / geo / uri_export | 格式解析、含认证与传输参数的身份去重、标签地区、客户端转换 |
| verifier / xray_verifier / quality / diagnostics | 核心隔离、兼容检查、重复 HTTP / HTTPS 检测、无敏感内容的错误摘要 |
| tasks / network_worker | 任务总时限、取消、单独下载进程及可复用节点检测进程池 |
| exporter / export_locations / client_exports | 完整版本事务、按客户端导出、目录迁移与导入说明 |
| subscription / progress / pipeline | 本机文件白名单服务、真实进度、任务编排与日志 |

`fetch.node_pools` 记录自选仓库的名称、分支、订阅文件和启用状态。新仓库默认停用，缺少文件时不能启用；来源列表显示停用项，但下载只遍历已启用项。旧 `public_sources` 在用户编辑来源时迁移，保留原启用状态。

## 获取与检测

1. 取得应用锁，检查检测核心身份；获取和检测必须有核心，重新导出允许仅结构校验。
2. 按本机历史通过率排序获取公开文件，最多 8 个可终止子进程同时下载。子进程以事件行传回连接、接收字节、解析和切换通道进度。缓存有效期内读取本机副本；过期发出条件请求。失败来源记录连续失败次数、下次重试时间；可用 24 小时内旧缓存但不更新其下载时间。手动测试可绕过来源退避，但不能绕过 API 限流等待。
3. 保留来源与节点身份的对应关系，计算全局去重数和各源独有数。候选按来源轮流分配，受总名额及单源贡献名额限制。历史低延迟节点最多预留总名额五分之一、上限 200；全部来源无数据时可回退重检历史，显式记录 history_only。取消和总时限异常不进入回退。零通过时仍保存来源检测结果以供下一轮排序，保留原导出。
4. TCP 预检完成数与实际 TCP 成功数分别记录；UDP 不执行 TCP 预检。
5. 分批校验核心配置，二分排除不兼容节点。进度完成数包含跳过项，实际检测计数不包含它们。
6. 每个节点进行两轮 HTTP / HTTPS 检测，每轮失败重试一次；只有两种请求返回 2xx 且各自延迟在阈值内，该轮才成功。Mihomo 延迟接口的返回还需核对该代理 `extra` 中对应测试地址的 `alive` 与最后一次记录；延迟接口本身成功并不能证明预期 HTTP 状态满足。两轮成功标记 stable，一轮成功标记 basic，零轮成功不导出。
7. 保留每节点延迟样本、质量结果、来源和真实验证时间。桌面获取及重新检测只原子更新 `data/library/free.json`，以 library_id 标记本批结果；失败或提交前取消保持上次节点库。用户在订阅导出页明确点击生成文件后，才运行导出事务。重新导出保留检测信息，不伪造新的验证时间。

检测仅衡量当时的请求响应，不测带宽，不保证长期可靠。国家/地区来自节点名称，不是定位结果。

## 进程与隐私

下载在单独可终止的子进程中执行，节点预检和探测使用最多 24 个按需创建的常驻工作进程。JSON 请求通过标准输入传递，响应逐行返回，认证信息不进入命令行。请求硬超时或取消时终止对应进程；任务结束回收全部拥有的进程。

核心在临时目录运行，使用随机控制端口和随机 secret，禁用 TUN；只终止当前创建的进程。错误输出在临时文件中收集，仅向上层提供预定义错误分类及退出码，不记录原始路径、节点或凭据。临时数据随进程退出清理。

缓存保存在本地 `data/source-cache`，内容含节点认证信息，不应发布。来源报告仅包含公开来源名称、散列身份、数量及无凭据的下载通道和错误信息。

## 导出事务

生成 `free.yaml`（图形客户端配置）、`free.mihomo.yaml`（独立核心配置）、`free-nodes.yaml`、两个 v2rayN 链接文件及报告。Mihomo 独立配置有显式本机监听端口，图形客户端配置不覆盖其端口。

Mihomo 存在时检查两份完整 YAML；无可用 Mihomo 时只执行结构和策略引用校验，报告和页面明确说明。Xray 检测不宣称完成 Mihomo YAML 语法校验。

发布及历史清理持有同一共享导出锁；不同数据目录使用同一导出根目录时也不能重叠处理。迁移同时锁住来源和目标，避免复制未完成的版本。准备三个客户端的便捷文件，失败则回滚；最后原子更新 current.json。只有完整版本才能生效。零节点、全部源失败、核心失败、检查失败和发布前取消均保留原版本。

原子指针切换是任务提交点；切换完成后任务视为成功，之后的取消或历史清理失败不能再标记为失败。清理失败记录独立提醒。默认保留 5 个历史版本，最少 2；不清理当前版本、无关文件或含链接的目录。目录迁移只复制白名单免费数据，旧位置保留；导出位置不能覆盖源码、构建、备份或 Git 元数据目录。

本机订阅服务只监听回环地址，检查 Host 并支持 GET / HEAD；文件和代目录不能通过链接访问其他位置。处理连接使用超时和守护线程，慢客户端不会阻止退出。白名单包括两份完整 YAML、纯节点 YAML、两种 v2rayN 文件。Gist、私人订阅输入、自建节点、合并订阅及 Base64 YAML 不在当前功能中。

## 报告

`report.json` 包含真实 verified_at、exported_at、counts.free、verification_core、export_core、config_validated、export_warning、节点来源、来源贡献和客户端转换原因。`last-run.json` 表示最近操作状态，不能代替连通性结果。
